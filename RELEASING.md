# Releasing Black Sparrow

One tag push releases every channel with the same version. All of them are on GitHub.

| Channel        | Produced by                                   | Name                                                     |
| :------------- | :-------------------------------------------- | :------------------------------------------------------- |
| GitHub Release | `release.yml` (cargo-dist)                    | `blacksparrow-<target>.tar.xz` / `.zip` + `.sha256`      |
| Installers     | `release.yml` (cargo-dist)                    | `blacksparrow-installer.sh`, `.ps1`, `.msi`              |
| Python wheels  | `publish-wheels.yml`, called by `release.yml` | `blacksparrow-<version>-py3-none-<platform>.whl` + sdist |

`release.yml` is generated by cargo-dist from `dist-workspace.toml`; regenerate it with `dist generate` (cargo-dist 0.32.0, pinned there) and never edit it by hand. A tag with a pre-release suffix such as `v0.2.0-rc.1` builds the GitHub release with the binaries only, without wheels.

## One-time setup

The GitHub release needs no setup: the workflows request the permissions they use (`contents: write` to attach the wheels, `attestations: write` and `id-token: write` for build attestations). Merge to `main` first, so the tag points at a commit that has these workflows.

## Releasing

1. Set the version in `Cargo.toml` and `src-tauri/Cargo.toml` (the Python package reads it from `Cargo.toml`). Update `DEFAULT_TAG` in `install.sh`, and add the version to `CHANGELOG.md`.
2. Check locally:

   ```bash
   cargo fmt --check && cargo clippy --workspace --all-targets -- -D warnings
   cargo test
   cargo run --quiet -- schema extract | diff - schema/extract.schema.json
   dist plan
   ```

3. Tag and push. The tag must match the version exactly:

   ```bash
   git tag v0.1.0
   git push --tags
   ```

4. Watch the **Release** workflow run. Order: plan, builds for 7 targets (each attested), GitHub Release created, then `publish-wheels` (wheels built, attested and attached to the release), then announce. A failed job can be re-run on its own: the wheel upload replaces files already attached.
5. Check the result: the release page has 7 archives, 7 `.sha256` files, the installers, 7 wheels and the sdist; installing a wheel by its URL gives `0.1.0`; `gh attestation verify blacksparrow-x86_64-unknown-linux-gnu.tar.xz --repo Shantodotdev/blacksparrow` succeeds.

## If something goes wrong

- A bad release is fixed with the next patch version; do not move a published tag, since apps pin wheel URLs and hashes from it.
- `dist plan` complaining that `release.yml` is out of date means `dist-workspace.toml` changed: run `dist generate` and commit the result.
- The Tauri desktop shell (`src-tauri`) is excluded from releases (`dist = false` in its `Cargo.toml`); only the `blacksparrow` CLI is released.
